    Loose ends

    • Real travel-time data. availability.py's travel_time_minutes() is a stub with no real data behind it. Ask the staff engineer or engineering manager for the real thing.
    • Manual override records. A routing override audit log shipped in 4.0 to track when a handler picks someone other than the recommendation, but we only have the original proposal, not the actual August/September entries. Ask engineering for the log.
    • Whether decay logic exists elsewhere. history.py flags the missing decay as an open question from 2019. Worth asking the staff engineer directly whether something outside this folder already handles it.
    • Capability tag data. The score has a third input — capability match — that isn't exposed anywhere we could check it against these responders.
    • Anything after 7 September 2026. Every number here stops there. Ask for fresher data before treating this as the current state.
    • The real, live score. It lives only in memory in the running system. Everything in the health lab above is a replay of the formula against real outcomes, not a reading of the actual stored number.
