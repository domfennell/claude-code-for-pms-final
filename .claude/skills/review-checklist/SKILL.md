# Review checklist

You're checking a brief against four plain, specific things — not a general
quality pass, not a rewrite, not a line edit for prose. Only these four.

## 1. Work out what you're checking

- If the student named or pasted a path, read that file.
- If they pasted the brief's text directly, use that.
- If it's ambiguous which file they mean, ask one short question naming the
  candidates you found, rather than guessing.

## 2. Run the four checks, in this order

For each one, decide **Pass**, **Partial**, or **Missing**, and quote the
exact line or heading that makes your case. Don't infer a pass from vibes —
if you can't point to a specific place in the text, it's Partial or Missing.

**1. Names who owns it.**
Pass: the brief says, in so many words, who decides or signs off — a named
person or role attached to the decision (not just listed as a stakeholder
somewhere). Partial: someone's named but it's unclear what they're actually
deciding. Missing: no named owner for the decision at all.

**2. Says how we'll know it worked.**
Pass: there's a concrete, checkable condition for success — a number, a
threshold, an observable behavior change, something you could actually go
verify later. Partial: there's a goal but it's not checkable ("make this
better"). Missing: no success condition anywhere.

**3. Keeps the same scope start to finish.**
Pass: the problem named at the start and the plan/fix described later are
the same scope — nothing new slipped in, nothing got quietly dropped.
Partial: mostly consistent, but note any specific drift you find (a new
ask that shows up mid-document with no setup, or a stated problem that
the plan doesn't actually address). Missing: the start and the end are
arguably about different problems.

**4. Explains the problem before the fix.**
Pass: a reader hits the problem/why-it-matters framing before they hit the
proposed solution, in document order. Partial: the problem is explained,
but after the fix, or interleaved confusingly. Missing: the brief opens
with a solution and never clearly states what problem it solves.

## 3. Report it

A short checklist, one line per check, in this order, each with its
verdict and a one-line reason pointing at the text:

```
✓ / ~ / ✗  Names who owns it — <quote or reason>
✓ / ~ / ✗  Says how we'll know it worked — <quote or reason>
✓ / ~ / ✗  Keeps the same scope start to finish — <quote or reason>
✓ / ~ / ✗  Explains the problem before the fix — <quote or reason>
```

(✓ = Pass, ~ = Partial, ✗ = Missing)

Then, only for anything not a full Pass, one short sentence on the smallest
change that would fix it — not a rewritten brief, not a list of other
issues you noticed along the way. If all four pass, say so in one line and
stop; don't look for more to critique.
